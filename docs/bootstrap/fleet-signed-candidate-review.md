# Fleet signed candidate review

This ADR-0062 source component connects genuine prepared-hook tickets to the fixed trusted SSH signer, existing final validation, and the native review completion producer. It does not publish a branch/PR, confer a pilot pass, or complete the fleet runtime command.

`signCandidateHook(ticket, policy)` reads the owned signing request and verifies the exact numeric repository/name and public key against trusted controller policy before using a key. The fixed adapter resolves an explicit non-secret key reference to `/etc/bootstrap/fleet-signers/<reference>.key`, audits its private-file/parent metadata, invokes trusted `ssh-keygen` over the exact unsigned commit, and passes the raw signed commit to `completeSignedCandidate`. That existing consumer verifies the signature and performs the isolated final check. There is no default-key search, ambient SSH agent, target-selected signing command or caller-provided pass result. A missing signer setting or unavailable key blocks the operation. This source neither selects nor enrolls a production signing identity.

Successful completion records a private authorization association between the actual checked handle and policy. It checks repository, base, source, prepared tree, complete commit plan and public-key hash. An ordinary `CheckedCandidate` proves completed validation and signature validity; it is insufficient for this route without the association established by the authorized signer.

The signer's 90-second budget covers host/key checks, signing and its temporary-directory cleanup. It ends before handing the signed bytes to final validation, whose owned ticket keeps the existing phase and operation bounds. Caller cancellation and policy validity are checked across that handoff and again before an authorized result can be returned. A valid longer final check is not discarded merely because the separate signing budget elapsed.

`reviewCheckedCandidate(checked, policy)` reconstructs a fresh workspace from the owned complete-history Git bundle. It validates raw objects, parent/tree identities, file modes/bytes, source hash and SSH signature without running target checkout hooks or filters. It checks Git configuration before subsequent Git commands and audits exact source/history/metadata before and after native review. The fixed native producer runs independently from the configured author session. Only its verified clean completion, unchanged workspace, successful awaited deletion and the original cleanup deadline can produce `ReviewedCandidate`.

`readReviewedCandidate(handle)` returns a frozen owned view containing `checked`, `policy`, `facts` and optional cancellation signal. Its facts contain exact checked-candidate facts, native-review facts, the configured signing principal, `independentExecution: verified`, `publication: pending` and `authority: none`. Copied objects cannot reconstruct the handle. The result remains tied to its source candidate, policy and cancellation lifetimes. It is evidence for the next governance/provenance/publication consumers, not a freshness lease or GitHub approval. Those consumers must recheck current identities, cohort/pilot/decisions and required provenance before either write.

Tests create real temporary Git merge history, binary/Unicode/newline paths, executable modes and ephemeral SSH signatures. They exercise repository/key mismatch, wrong/unavailable key, changed source/configuration/refs, malformed native completion, cancellation, and failed/retried cleanup. Linux host eligibility, prior isolated validation, runtime policy and native child execution are explicitly substituted in these consumer tests. Actual Git and SSH signing/verification run; no existing key or model is used. These tests do not replace the isolated backend's own evidence or qualify production native containment.

The next concrete consumers are the one-repository App session/publisher, governed runtime/CLI, and native-lineage public provenance gate. Missing production signer/profile configuration or unsupported required provenance remains a publish blocker. App installation, key enrollment, model transmission and real fleet mutation require separate operational authorization; none occurs through these source tests.
