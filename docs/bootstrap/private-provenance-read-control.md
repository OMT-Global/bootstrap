# Approved private provenance read-control source

This is an inactive source component for #161, governed by ADR-0060. The owner approved source/tests after independent security design review; real capture, AWS/App/key setup, enrollment, privileged runtime, external model transmission and gate activation remain unauthorized. Existing synthetic APIs remain synthetic-only.

## Executable boundary

`createPrivateReadCoordinator` consumes canonical signed `ReadRequest`, `ReadApproval`, `Delegation` and individual-approval `ReadRevocation` messages from the approved control protocol. It performs full-message Ed25519 signature verification against an externally configured, purpose/owner/time-scoped public keyring. No embedded key enrollment or `verify(): true` approval path exists. The ordinary approver must be the exact enrolled Codex workload and key named in the root-signed delegation. Root authority may revoke approvals; it cannot substitute its key for a Codex read approval.

`read` snapshots request bytes before awaiting adapters. It authenticates the control signatures/context, conditionally reserves one deterministic approval key, verifies a signed durable attempt acknowledgment, rechecks authority/state before decryption, accepts a verified bundle from the fixed decrypt producer, validates category schemas/credential exclusion, rechecks current authority, consumes the reservation, and requires a signed completion acknowledgment before returning an owned buffer. Failure returns a fixed diagnostic. Mutable owned plaintext buffers are cleared best effort. The recipient owns the returned buffer and any onward copy; no delivery receipt or remote erasure is claimed.

`revoke` authenticates root or the exact issuing Codex key and binds delegation/approval/digest. An issued approval with a future notBefore can be revoked now: issuer/scope/chronology verification is separate from read-usable-now checks. An absent approval becomes a revoked tombstone through the same conditional-create key used for first use. Initializer/revoker races read the winner; neither retry nor restart overwrites a tombstone. Existing spent authorization returns `already-spent` and is never described as prevented. Repeated revocation rechecks durable state and audits it. Delegation-wide revocation is a current-configuration epoch/draining operation for the future fixed runtime, not an unsupported fallback in this individual-approval API.

## Operator and test limits

The new private-control keyring requires each Ed25519 x value to decode to exactly 32 bytes and round-trip as canonical base64url. Noncanonical aliases for the same mathematical key cannot acquire distinct purpose fingerprints. Existing public codec/wire behavior is unchanged.

Read windows are checked after awaited ledger reads immediately before decryption and spending, and after the spend CAS acknowledgment. A CAS acknowledgment arriving after expiry withholds plaintext and leaves spent/uncertain state terminal. Confirmed timely spend remains the approved authorization point: expiry occurring only during the subsequent completion-audit wait does not introduce a new delivery-expiry policy; the verified completion acknowledgment still gates release.

The state key hashes canonical `{domain:'bootstrap-approval-state-key',delegationId,approvalId}`. It excludes configuration epoch and operation ID, so a restart/new operation cannot evade an existing tombstone. Provider ambiguity can leave a safe stranded reservation; no successful read is inferred from an incomplete call. Exact-state reconciliation is required, and spent/failed/revoked approvals cannot be reused. Revocation/expiry checks and final authorization have an acknowledged in-flight race; no global atomic revocation is claimed.

Application audit events remain private. Completion means authorization and decryption finished; a later connection failure can leave delivery unknown, and another attempt requires a new approval. Literal credentials and raw traces/prompts/customer records remain excluded. Pattern checks are defense in depth and cannot certify arbitrary summary prose as secret-free.

Validation uses focused read-control plus existing synthetic/public codec regressions, repository typecheck/build and the full test suite. No deployment, actual provider permission, real-data capture or retention assertion follows from a test pass. There is no lint script in the current package; do not report an unrun lint command as passing.
