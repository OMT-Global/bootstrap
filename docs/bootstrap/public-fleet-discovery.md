# Public fleet discovery

`bootstrap discover-public-fleet --org OMT-Global` reads public GitHub repository metadata and, when possible, a source-bound root `project.bootstrap.yaml`. Add `--json` for machine-readable output. It never opens PRs or changes repository settings. It lists archived and forked repositories with flags; disabled or unsupported entries are explicit. In this report, `managed` means only that a root manifest normalized and matched the observed public repository identity; it does not prove ownership-sidecar state. A complete result means the bounded observations and rechecks completed, not that every repository is safe to upgrade or eligible for a pilot. JSON records the scope and explicitly marks policy, drift, exception and pilot verification as `unverified`.

Organization enumeration is always anonymous and restricted to public repositories. Object reads are anonymous by default; public rate limits can leave a result incomplete. A future separately trusted GitHub App broker may pipe a short-lived, narrowly scoped read capability into the command with `--read-token-stdin`. Do not put the capability in command arguments, shell history, files, environment variables or logs. Terminal input is rejected to avoid echoing it. The command does not establish App identity, token expiry, installation scope or least privilege: the trusted broker must establish them separately. No broker or real credential is configured by this command.

Reports contain validated public repository names and IDs, default branches, flags, object identifiers, byte counts and fixed outcome codes. For successfully normalized manifests they also show the normalized repository class, the safely renderable Flow policy ref and its declared SHA-256, and the number of declared exceptions. These are claims observed in the public manifest: they do not validate the referenced policy or the exception evidence. Unsafe or overly long refs are marked `unrenderable` without displaying their contents. Reports do not include raw manifests, credentials, exception details, or arbitrary provider error text. An incomplete report exits nonzero; its collected prefix cannot be used to retrieve manifest bodies. A 404, token scope failure, changing identity, invalid page, rate limit or timeout is not treated as an unmanaged repository. Source observations are point-in-time and cannot eliminate later changes.

Discovery does not resolve policy versions, calculate managed-file drift, authenticate exceptions or pilot outcomes, or open upgrade PRs. Use the existing `upgrade-plan` only with separately prepared and validated inventory input; the two commands are not yet integrated. Do not use a discovery report as approval, provenance, write authority, or proof of issue #62 completion.
