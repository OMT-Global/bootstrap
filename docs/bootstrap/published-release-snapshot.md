# Published release snapshot prototype

`publishedReleaseSnapshotScript()` emits an **inactive** Python function, `collect_published_release(provider, authorize, request)`, for a later generated workflow. It performs no HTTP, reads no credentials, performs no mutation, and is not called by a workflow. It collects a bounded observation of one already-published release; missing, inaccessible, draft, ambiguous, malformed or mismatching releases all raise `SnapshotError`. Failure never implies release absence or permission to create.

`request` has exactly `repository`, `release_id`, `tag`, and `commit`. The requested repository and tag use the structural/safe-ref restrictions of the frozen comparator; this does not establish that a repository or ref exists. Before reading provider data the function calls the injected trusted `authorize(provider, repository)` function, and calls it again before returning. The trusted function must raise on any inability to verify that the same authenticated provider principal has the required repository write authority and complete visibility into releases, drafts, and assets. It must reject insufficient, ambiguous or changed authority. Returning `None` is only its success convention; an arbitrary callback, Boolean, input label or `next: null` does **not** authenticate a principal, establish draft visibility or prove a complete listing. The callback and provider implementation do not exist here and must be independently designed and reviewed. Fake callbacks used by the tests prove only control flow.

The injected `provider` is trusted code, not data. It must use the same authenticated principal throughout, bind each response to its exact endpoint/arguments, enforce raw-response byte limits, reject duplicate JSON keys and all HTTP/transport/partial/API errors, follow only same-provider pagination, and establish complete and stable observations. For example, it must not transform an unauthenticated public response or a failed page into an empty terminal page. It must independently establish an authoritative latest-release ID or authoritative no-latest result. Its normalized methods are `repository(repo)`, `releases(repo, cursor)`, `assets(repo, release_id, cursor)`, `tag_ref(repo, tag)`, `tag_object(repo, sha)`, and `latest(repo)`; these are an internal prototype interface, **not** a claim about GitHub's wire format. Page objects have exact keys `items` and `next`; cursors are opaque to this function. Adapters must restrict actual network URLs and pagination links separately.

The collector validates normalized structures, exact repository identity, unique numeric release IDs, a unique matching non-draft release and exact requested release ID, bounded pages/cursors/asset counts, unique asset IDs/names, uploaded state, nonnegative exact sizes, authenticated SHA-256 labels from the trusted provider, authoritative latest ID present among the observed published releases, and the requested commit via lightweight or bounded annotated-tag chains. It resolves the tag before and after collecting assets and repeats the authority callback. Null notes for the selected release fail; unrelated releases may have null notes. No empty asset set, missing/unsupported digest, malformed input, next-page loop or tag mismatch is accepted. Asset records returned use the frozen comparator's schema (`provider-sha256` is a structural label, not authentication). Calculating digest from authenticated downloads is not implemented; a missing provider digest fails closed.

A successful return is a candidate `actual` record only. The future caller must bind expected metadata and digests to independently approved staged bytes, pass the candidate and expected record to the existing comparator, enforce release/tag/asset writer boundaries, and revalidate immediately before any mutation or promotion. Invoke the comparator in a separate isolated Python process, not the collector's namespace: the comparator executes immediately at top level. Its 4 MiB bound applies to the **complete serialized expected-plus-actual envelope**; per-field and asset bounds here do not imply that bound holds after JSON escaping, so the caller must reject an oversized envelope before invoking it. This prototype does not establish freshness, authenticate bytes, prove provider permissions, prevent races, provide atomic release publication, recover drafts, protect tags, or authorize a release. Even rechecking the tag leaves a concurrent movement window. Live token visibility and GitHub pagination/response mappings require independent documented and controlled integration evidence before use.
