# Published-release comparison primitive

`publishedReleaseVerifierScript()` returns a self-contained Python 3 program intended for a future generated release workflow. It is not currently called by the generator, any workflow, or the release CLI. It reads one bounded JSON object from standard input and exits zero with `{"eligible":true}` only when all required facts match. Invalid, missing, ambiguous, or mismatching input produces a generic error and nonzero exit; callers must check the exit status and must not infer absence or create a release from failure.

The version-1 envelope has exact keys `schema_version`, `expected`, and `actual`. Both records have `repository`, positive `release_id`, literal `tag`, full lowercase Git `commit`, literal `notes`, boolean `prerelease` and `latest`, and a nonempty `assets` array. Actual also has boolean `draft`, which must be false. The latest booleans must come from a separately established policy and authoritative observation; the comparator never infers latest from prerelease or creation order. Repository names use a bounded ASCII `owner/repository` structural subset, allow managed-user underscores, and compare case-insensitively; this does not prove canonical existence or spelling. Tags must be valid safe Git tag refs and cannot begin with a dash. All other strings compare exactly without whitespace or Unicode normalization. Notes are compared as exact UTF-8 text. Null notes do not mean empty notes.

Each expected asset has exact keys `name`, `size`, `sha256`, and `digest_source`; the source label must be `approved-bytes`. Each actual asset additionally has a positive stable `id` and `state` equal to `uploaded`; its source label must be `provider-sha256` or `authenticated-stream`. SHA-256 is exactly 64 lowercase hexadecimal characters, without an algorithm prefix. The complete flat-name sets, byte lengths, and digests must match; order does not matter. Duplicate names or IDs, missing or extra assets, unknown states, and missing or unknown digest sources are rejected. An ordinary selected asset named `SHA256SUMS` is treated like any other asset. Assets are bounded to 1,000 per record, names to 1,024 UTF-8 bytes, notes to 1 MiB each, integers to the exact JSON-safe range, and the whole input to 4 MiB. Duplicate JSON object keys and non-finite JSON numbers are rejected.

**Trust boundary:** The primitive compares supplied facts; it does not authenticate them. Source labels are structural declarations, not proof. Before calling it, an adapter must bind the expected release ID, metadata, and byte lengths/digests to the approved exact release target and verified staged bytes; independently resolve the remote tag to a full commit; authenticate the repository and actual release identity; and obtain complete, stable, paginated release and asset observations. Every actual asset record and its digest must be bound to that exact authenticated repository and release ID. A provider digest must be authenticated and explicitly identified as SHA-256; where it is unavailable, the adapter must calculate a digest from a bounded authenticated download by immutable asset ID. The actual `latest` observation must be separately authenticated and compare its stable release ID with this record's release ID; a false value also requires authoritative identification of which release is latest, or an authoritative no-latest result. Partial API pages, hidden drafts, API failures, null bodies, and unverified source data must not be transformed into valid records.

The comparator does not access the filesystem beyond standard input, make network requests, acquire provider data, establish visibility, validate signatures, verify tag protection, or perform publication. A match is point-in-time evidence only: concurrent release, tag, asset, or latest-pointer changes remain possible. A workflow must enforce its authority boundary and recheck identities before postpublish work and promotion. This primitive cannot prove atomic publication, recover drafts, or safely replace an existing asset. Provider integration and policy review are required before use.
