# Source release archive verification

`verifySourceReleaseArchive` is an inactive prerequisite for Bootstrap's repository-source release. Given an owned `VerifiedGitSnapshot`, an approved compressed archive, and separately authenticated commit, tree, tag and compressed SHA-256, it hashes the archive, decompresses it with an output bound, rebuilds `git archive --format=tar` for the exact commit in an isolated data-only repository, and compares every uncompressed byte. The expected `bootstrap-<tag>/` prefix and Bootstrap's existing version grammar are enforced. Different gzip encodings are accepted only when the supplied compressed bytes match the independently approved digest.

Snapshot construction checks the complete supplied regular-file inventory against the exact Git tree and commit. The data repository is temporary and uses the existing isolated Git environment; committed `.gitattributes` archive rules apply, while ambient Git configuration and the original repository's `.git/info/attributes` are not imported. The archive therefore represents Git's archive semantics for the commit, including any committed `export-ignore` and `export-subst` attributes, rather than a promise that every tracked file is included. Symlinks, submodules, and snapshots exceeding the existing data-repository limits are unsupported and fail closed. Compressed input is capped at 64 MiB, and the uncompressed tar and Git output at 8 MiB. The Git operation has the existing 30-second process bound. Different Git implementations or unsupported archive behavior can cause a safe mismatch.

The caller must authenticate the expected commit and tree, authenticate the approved compressed digest, and independently bind these archive bytes to the selected successful preflight artifact and attempt. This check does not prove any of those authorities, validate the other release assets or notes, inspect or publish a GitHub Release, protect remote tags, or authorize publication. It trusts the selected Git executable and the owned isolated repository against same-user mutation, as does the existing data-repository helper. No workflow or CLI calls this prerequisite yet.
