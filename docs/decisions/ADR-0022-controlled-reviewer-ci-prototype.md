# ADR-0022: Synthetic native reviewer platform probe

Status: Accepted

Scope: Source and CI prototype only. Native Linux support remains unproven until the exact hosted run passes.

Date: 2026-11-08

Governing issue: [#62](https://github.com/OMT-Global/bootstrap/issues/62).

## Context

A controlled reviewer must keep authentication outside its tools' readable filesystem policy. Codex 0.167.0 writes refreshed FILE OAuth credentials by creating locks and a sibling temporary and replacing the destination. A readonly single-inode mount cannot support that persistence. The existing API-key-in-FILE mode does not refresh and is the bounded candidate tested here. No operator credential is inspected or provisioned.

Native restricted Linux execution requires bubblewrap/user namespaces. Compatibility with Docker's unchanged default seccomp, dropped capabilities and no-new-privileges cannot be inferred from a successful backend test or source inspection.

## Decision

Wire the synthetic-only host probe to the existing full-validation entrypoint, after normal checks and actual backend Docker tests. Its fixed fixture producer and Dockerfile are the prerequisite defined by ADR-0026. Standard, smoke and fast profiles perform no new download or container activity. This second stage owns the host, the manifest and extended-script projections, this decision, a dedicated host test, and the existing entrypoint test. The entrypoint test retains all ten cases and changes only the expected Python command; all 63 original host cases remain in the dedicated test.

Use the complete official Codex 0.167.0 Linux amd64 musl package from source commit `086ccc833bc9cf01024ad2dd6af7dbd421b6bf9a`, archive SHA-256 `3bbf75e83de6b58aed28f2cf6e33ad423ec31fd4700a1457b94be557ea5a7c6e`. Exact size/hash limits apply to every download. Verify package, extracted CLI and bubblewrap signatures offline with fixed Cosign 3.1.4, exact workflow identity/issuer, transparency evidence and the SHA-bound root-signing snapshot at `c9bda74ad2221f938f7d2e0295ca3aad2da710a8`. Reject archive links/devices, unsafe paths, unsupported modes, duplicates, collisions or expansion beyond 2 GiB/4096 members/depth 32. Preserve the complete package, its notices and voice license inventory, plus pinned Codex, bubblewrap and ripgrep notices.

Delegate acquisition, extraction and all three mandatory offline signature checks to the fixed sibling `reviewer-artifacts.py` module at the accepted ADR0023 boundary. Call its default `stage()` exactly once with a fresh private empty owned directory and the original absolute 15-minute host deadline; never call metadata preparation or a standalone acquisition CLI first. Preserve its returned verified context, complete package/notices, artifact evidence, retained bundle bytes and public provenance without rewriting them. Host and artifact environments and clocks remain separately cleared and bounded.

Build only an ephemeral public-input image on the existing immutable MCR six-tool base. No registry image is published, package installer runs, workflow/pin changes, real authentication, helper source vendoring or new service is introduced.

The host supervisor remains outside each owned PID/cgroup namespace. Each fixture uses readonly root, no network, all capabilities dropped, no-new-privileges, the ordinary numeric UID/GID, memory 2 GiB/swap zero, 128 PIDs, two CPUs, a 256 MiB/16384-inode noexec tmpfs, bounded hard resource limits and bounded output. The 15-minute prototype deadline has independent bounded cleanup. These timings do not alter production backend or broker limits.

Require the supported daemon security-option families exactly once: `name=seccomp,profile=builtin` and `name=apparmor`; reject rootless, unconfined, missing, malformed, duplicate or other profile values. Daemon capability is separate from the effective fixture observations. Before any `GO`, require the private READY fields `seccomp` to be the integer 2 and `apparmor` to be `docker-default (enforce)`, together with true PID1, readonly-root, safe-mount, zero-capability and no-new-privileges predicates. The producer measures Seccomp from `/proc/self/status` and requires the raw AppArmor bytes `docker-default (enforce)\n` from `/proc/self/attr/apparmor/current`. Require its workspace statvfs flags to be an unsigned 64-bit integer containing NOSUID, NODEV and NOEXEC, without RDONLY, as well as the existing tmpfs type and positive bounded byte/inode capacities. Preserve benign extra READY fields. These mandatory private fields do not expand the public evidence schema or diagnostic enums. A supported label and mode are observations under the trusted fixed host/image assumption; they do not attest policy contents or an untrusted kernel.

Mask the default `/dev/mqueue` destination with a fixed empty root-owned readonly tmpfs (`ro,nosuid,nodev,noexec,size=4096,nr_inodes=16,uid=0,gid=0,mode=0555`). This narrows the launch profile to satisfy the existing writable-mount predicate; do not add a path allowlist or relax that predicate. The sole writable workspace tmpfs and all existing limits/security controls remain. This is a filesystem-view hardening measure, not proof that all kernel IPC syscalls are disabled. Exact Docker override/mount behavior and readiness remain subject to the hosted full probe. [Docker tmpfs contract](https://docs.docker.com/engine/storage/tmpfs/).

Preserve the exact 17179869184-byte soft and hard address-space limit through the pinned image’s fixed `/usr/bin/prlimit` exec-form entrypoint, before the original isolated Python command and its descendants. Docker does not support its `--ulimit as` option, so remove only that unsupported item. The trusted launcher and loader start before AS is installed; all other existing Docker controls already apply. The fixture requires the measured inherited pair before any resource setter, the host validates it before `GO`, and mechanical evidence retains it. Missing/denied launchers and incorrect inherited limits fail closed without installation, shell fallback or profile relaxation. Actual execution under this profile still requires the exact hosted run. [Docker CLI contract](https://docs.docker.com/reference/cli/docker/container/run/#set-ulimits-in-container---ulimit); [util-linux command contract](https://manpages.debian.org/bookworm/util-linux/prlimit.1.en.html).

Before staged public evidence is retained, an optional fixed bootstrap-stage label identifies only the attempted Docker-info, artifact-directory, artifact-stage or returned-evidence operation. An optional HTTP status is retained only for an exact standard-library HTTPError with a strict integer in the fixed public-status allowlist; no exception text, URL, headers or body is exposed. Clear the stage immediately after successful evidence retention; no bootstrap diagnostics are published for later image, native or auth failures.

Mechanical failures before readiness may retain a fixed admission-stage enum, the bounded numeric inherited address-space pair, and an optional process/mount substage with only observed boolean predicates. Capture NoNewPrivs only when its original short-circuit operand executes; an unevaluated comparison remains absent. Clear process context after that group succeeds. No exception text, stderr, raw paths, environment, auth or later/native output is published. Keep the fixture admission failure separate from the host’s missing-readiness/group failure and final deletion outcome. Existing diagnostic stages group the process-security observations without identifying an unobserved failed subpredicate. Preserve the first-native stop and the control flow before cleanup.

Run mechanical admission, byte exhaustion, inode exhaustion and detached-descendant teardown before the native sandbox canary. The native canary proves allowed workspace reads and denied private reads, writes and network. Its first failure returns unsupported/native-sandbox, stops all later cases, and leaves mock/provider request counts zero. No capability, seccomp, AppArmor, sysctl or inner-sandbox relaxation is selected here.

Only after that gate, individually mount one newly generated fake auth inode readonly and an adjacent independently generated public configuration file readonly. Do not mount a whole home, copy auth into the runtime directory, use environment-key fallback or read an operator's home. Native login-status output may reveal masked key fragments; capture/classify/discard it privately under a strict cap. Accept only API-file mode; reject OAuth/unknown and reject auto/keyring configuration before native auth or mock launch.

The API fixture uses the actual native CLI against one test-owned loopback Responses mock in a network-none container. It clears inherited environment credentials, checks that the bearer came from the fake FILE, handles the native authenticated WebSocket 426-to-SSE fallback, counts all requests and requires schema-valid output. Persistence negatives verify readonly inode metadata/bytes and parent contents. No OpenAI service or real key is used.

Emit a public `CONTROLLED_REVIEWER_EVIDENCE` UTF-8 JSON wire line capped at 65536 bytes including its prefix and LF. Check the compact encoding and any bounded failure fallback before output; retain only bounded valid fallback context and the omitted compact-byte size/hash. Save the same checked compact JSON bytes plus LF in the ignored local report. Bind actual checkout head, repository/run, public assets/source hashes, image, completed cases and cleanup. The host owns container/image removal and the entire temporary root, including staged public artifacts and fabricated auth files. Its independent 60-second aggregate cleanup clock bounds removal; success is emitted only after removal and verified temporary-root absence. Within that same clock, attempt each remaining owned container and the owned image after an earlier removal failure, retaining a false cleanup result. Every command retains its existing 20-second cap and the aggregate deadline prevents starting later commands after expiry. A successful `docker rm -f` for an already absent container is success. Temporary-root removal remains subject to the same deadline; failure or expiry cannot report cleanup success. Cleanup failure takes precedence over runtime or artifact success. The existing immutable callee's generic evidence artifact is unchanged; the custom record is visible in the bounded job log. Missing/failed mandatory cases cannot report success.

After the host has verified the container cgroup and before stopped-container inspection, read `cgroup.procs` directly during the existing two-second teardown check and accept `FileNotFoundError` as a deleted group. Initial cgroup identity/admission stays outside this scope and must succeed before `GO`; populated groups and all other errors still fail closed. The only filesystem work inside the scoped suppression is the two membership reads. Its fixed standard-library clock/sleep calls and existing `require` have no real missing-path operation; keep new filesystem work or callbacks outside this boundary unless separately reviewed. The catch is lexically wider than the reads: fabricated replacements of clock/sleep could inject a swallowed `FileNotFoundError`, so this is not a claim about arbitrary monkeypatches. Later Docker inspection/removal remains outside the suppression. [Kernel cgroup lifecycle](https://docs.kernel.org/admin-guide/cgroup-v2.html#processes); [CPython clock/sleep implementation](https://github.com/python/cpython/blob/v3.12.8/Modules/timemodule.c).

Retain at most six fixed command-phase records for image history and the first mechanical case, with exit status, whether that status was observed before supervisor cleanup, and byte counts/hashes for stream bytes admitted by the existing combined bound. EOF flags distinguish complete streams from bounded prefixes. Fixed first-case event and host-stage flags distinguish Docker CLI, fixture protocol and host cgroup validation boundaries without attributing an unobserved cause. Emit no argv, stdout/stderr text, paths, environment or socket content; later native/auth cases remain uninstrumented. These diagnostics cannot recover stderr discarded by an earlier run.

## Validation and limits

Mac host validation uses fixed fake adapters for daemon and READY admission, evidence, ordering, inherited limits, cleanup and deadline controls. These tests neither run Docker nor execute native reviewer/provider activity. Source compilation, manifest projection and entrypoint/full repository checks are required when this stage is adopted on its actual reviewed producer parent. The host process-group negative exposed EPERM when signaling an already-exited Python child on Mac, including outside the filesystem sandbox. It is explicitly Linux-only; the mandatory Linux path executes output/deadline/group controls before any native/auth/mock activity. No local process-control or Docker support is claimed.

No production review API, receipt, signing capability, executor CLI, publication authority or actual installed-autoreview integration is added. The runner does not have the external helper installed; a direct native/mock success would not establish a complete autoreview receipt or permit fleet publication. Operator OAuth support remains unavailable under this selected mount profile. Future integration and any launch-profile amendment require their own concrete review.
