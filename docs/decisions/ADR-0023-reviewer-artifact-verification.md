# ADR-0023: Pinned public reviewer artifact verification

Status: Accepted

Scope: Source and CI preparation only; no native reviewer, runtime, deployment or fleet publication approval. Hosted preparation passed; the default pinned path remains unproven until separately run.

Date: 2026-11-08

Governing issue: [#62](https://github.com/OMT-Global/bootstrap/issues/62). This prerequisite does not complete its native reviewer or fleet publication contract.

## Context

The public native reviewer prototype at `f410d6bdda984778db1e049d51287617f80dbe35` reached archive extraction in [run 42537783405](https://github.com/OMT-Global/bootstrap/actions/runs/42537783405), then failed before image construction or native execution. The discarded process stderr prevents attributing the exact observed failure. Independently, its inputs are incompatible: the official OpenAI release signs legacy bundles and Cosign 3.1.4 rejects a legacy bundle with `--trusted-root`.

The artifact prerequisite extracts the existing public download, hash, archive, notice and Cosign responsibilities. Native sandbox, Docker fixture, authentication, mock provider, helper integration and publication controls remain outside this change.

## Decision

Keep the exact Codex 0.167.0 source `086ccc833bc9cf01024ad2dd6af7dbd421b6bf9a`, complete package, native and bubblewrap hashes, Cosign 3.1.4 binary, workflow identity and GitHub Actions issuer. Retain trusted-root snapshot `c9bda74ad2221f938f7d2e0295ca3aad2da710a8`, SHA-256 `6494e21ea73fa7ee769f85f57d5a3e6a08725eae1e38c755fc3517c9e6bc0b66` and offline signature verification. Do not replace the root document with raw PEM overrides or ambient TUF: the modern verifier uses its Rekor, CT and CA validity metadata.

Separate public metadata acquisition from ordinary verification. Explicit CI-only `--prepare-metadata` runs pinned Cosign's official `bundle create --artifact FILE --bundle LEGACY --out STANDARD --rekor-url https://rekor.sigstore.dev` under a cleared environment and a fresh private temporary home. This performs a public Rekor lookup; it is not an offline conversion and is never invoked by `stage()`.

A shared strict, duplicate-free JSON parser binds certificate DER, signature, Rekor canonical body bytes, log ID, global index, integrated time, artifact digest/algorithm and hashedrekord 0.0.1 to the SHA-pinned legacy inputs. Require one existing log entry, promise, proof and checkpoint; both original and converter SETs must be nonempty valid base64. The official converter fetches a current Rekor entry, whose SET can be re-signed for the same immutable payload. This is a primary-source fact, not the observed failed field of run 42540530709, which reported only `bundle` before verification.

Cosign constructs media type `application/vnd.dev.sigstore.bundle+json;version=0.3`, `verificationMaterial.certificate.rawBytes` and `messageSignature`. Bytes use standard base64, int64 fields use decimal strings, and the original body is not recanonicalized. The proof index is relative to its individual tree; it must not equal the original global log index. The audit permits that distinction and requires the proof/checkpoint structure to remain present.

Retain the exact RAW official converter bytes independently. Only after every immutable binding passes, replace the existing `verificationMaterial.tlogEntries[0].inclusionPromise.signedEntryTimestamp` leaf with standard base64 of the original pinned legacy SET bytes. Preserve all other parsed values and types, object members/order, array order, supplemental fields and the complete proof/checkpoint. Serialize the candidate as readable indented UTF-8 JSON, then run the strict final audit requiring the original SET. There is no caller-selectable bypass. The unchanged pinned offline verifier independently checks both the retained original SET and the supplemental inclusion proof when both are present; the parser performs no custom cryptography.

`finish` snapshots the audited candidate bytes and requires equality to the original SHA-checked pinned bytes or preparation-created normalized bytes before verification. After all three unchanged verifier calls succeed, require exact reread equality for every candidate before setting signature success or metadata. Derive hashes, sizes and emitted base64 from the retained verified bytes, with no unchecked later reread. These checks bind the selected bytes and observed verification interval; they do not claim universal immunity to concurrent filesystem changes.

Only after all three exact normalized candidates verify and cleanup succeeds, emit three bounded `REVIEWER_ARTIFACT_RAW` records and the existing `REVIEWER_ARTIFACT_EVIDENCE` summary with candidate `publicBundles`. RAW and candidate bytes/hashes are separately identified; failed or unverified candidates are never emitted. The reviewed candidate bytes are pinned in `scripts/ci/reviewer-artifact-bundles/{package,native,bwrap}.json`. Exact RAW acquisition evidence is retained separately in the `raw/` subdirectory and is never selected as a runtime candidate. An incomplete pin catalog fails before acquisition; missing, modified or truncated candidate files fail before verification. Default `stage()` performs no normalization, automatic preparation, live trust fallback, configurable endpoint or native execution.

The genuine preparation-only WIP at `1e05a1eb0431a06a28b0f23d7f90ccfaffc2848f` passed 807 ordinary and 16 real Docker tests in [run 42540530709](https://github.com/OMT-Global/bootstrap/actions/runs/42540530709), then returned `bundle` with cleanup true and no verified/raw/candidate payload. Static diagnostics now identify only fixed artifact/field and shape/mismatch tags, never values, JSON keys, paths, exception text or observed lengths. Deadline and cleanup errors retain precedence.

The manifest and scoped generated full-profile entrypoint now use default `python3 scripts/ci/reviewer-artifacts.py`, reading only the three pinned candidate files. Explicit `--prepare-metadata` remains available solely as the separate manual CI preparation operation; default execution never invokes it. The existing immutable reusable caller `913b298fab0fb008796011d940ee7362a347659d` and all runner/workflow settings remain unchanged. Fast, smoke and standard profiles perform no new artifact downloads.

The reusable `stage(directory, absolute_deadline=None)` accepts only a fresh, private, empty owned directory. It returns paths and metadata for verified public artifacts, never a native-support, model-review or fleet receipt. It has a hard 15-minute acquisition budget capped by an earlier caller deadline. Its CLI owns a separate 60-second cleanup budget. Subprocess combined output, process groups, downloads, extraction members, paths, types, modes and expanded bytes remain bounded. Only the three fixed public Cosign verification calls emit JSON-escaped stderr and exit status; no runtime or authentication output is involved.

Preserve the complete official package layout and all package notices, including voice resources, plus the pinned Codex, bubblewrap and ripgrep notices. The download SHA check precedes archive parsing. Extraction rejects links/devices, traversal, unsafe modes, duplicate names and file-parent collisions within the existing 2-GiB, 4096-member, depth-32 envelope. The official pinned archive has already been observed to contain 52 members and 540530246 expanded bytes; this source change does not claim a new extraction or verification run.

## Public output contract

Successful preparation emits exactly three `REVIEWER_ARTIFACT_RAW ` lines in package/native/bwrap order. Each suffix is JSON `{schema:1,artifact,bytes,sha256,base64}` for the exact RAW converter file. A final `REVIEWER_ARTIFACT_EVIDENCE ` line retains the existing summary and candidate `publicBundles[name] = {bytes,sha256,base64}`; `rawBundles[name] = {bytes,sha256}` identifies RAW data, `bundles[name]` identifies normalized candidates and `bundlePreparation` is `original-set-only`. Each RAW line including prefix and LF is at most 131072 UTF-8 bytes; all RAW lines plus summary including LFs total at most 262144 bytes. Check all bounds before printing any payload. Overflow emits a small failed summary with reason `evidence-limit`, plus the bounded failure diagnostic described below; successful payload wire bytes are unchanged.

The watcher must require the exact reviewed head/run/callee and successful final run, all three unique fixed artifact names, final `ok`, `cleanup` and `signatureVerified` true, then validate decoded sizes and SHA-256 for RAW and candidate data against both payload and summary metadata. Missing, duplicate, truncated or inconsistent records fail closed. On verification or cleanup failure, emit one failed summary without RAW records, candidate `publicBundles` or a `signatureVerified` claim. Public conversion data stays in a private owned temporary directory until cleanup; no auth/runtime data is involved.

## Validation and limits

The renewed-SET before control exercises the actual old `prepare_with_clock`/`main` path with stubbed converter/verifier: it rejects with zero verification calls and cleanup true. The amended path reaches the same three offline verification argument lists. Full-tree one-leaf retention, immutable tampering, duplicate/missing/empty SETs, each verifier failure, cleanup failure, raw exact-byte retention, diagnostics privacy and aggregate output bounds are covered without real cryptography. The existing entrypoint tests retain ordering and cheap-profile checks and add the exact preparation command and its failure propagation. The manifest and generated script are backed up and the scoped projection is compared byte-for-byte; all 13 existing plan drift classifications are preserved.

Mac validation does not download or execute the Linux package or Cosign, start Docker, inspect operator authentication, contact a provider or create a model review. The actual preparation conversion and trusted-root signature checks passed in run 42543713399 as recorded above. The default pinned route still requires its own exact-head hosted run. Native support, complete autoreview receipts and fleet publication remain unproven. The baseline doctor reports local GitHub authentication as a warning; no authentication change is part of this prerequisite.


## Failure-only observation context (2026-11-09)

At exact `d02c2273b09b512cdcba03b7cdeff4851f852602`, full run42581072744 passed the first ordinary suite and16 actual Docker-suite tests, then emitted default `preparation:false`, `ok:false`, `cleanup:true`, `reason:unsupported`. No completed signature diagnostics or release-evidence artifact were emitted; the second ordinary suite was unreached. The underlying cause is UNKNOWN. Missing post-wait signature output does not prove no verifier process started. This addition provides observation only, not a root-cause fix, alternate verifier, retry, preparation, resource change or runtime support claim.

A caught CLI failure emits exactly one compact `REVIEWER_ARTIFACT_DIAGNOSTIC ` JSON line before the existing failed evidence summary. Fixed field order/schema is `{schema:1,stage,assetIndex,lastHttpState,lastHttpStatus}`. Its UTF-8 prefix+JSON+LF is bounded by192bytes (the current frozen enum/domain worst combination is136bytes). The fixed stage enum is `workspace`, `clock`, `context`, `command`, `download-setup`, `download-open`, `download-read`, `download-write`, `download-hash`, `layout`, `extract`, `candidate-read`, `candidate-write`, `bundle-audit`, `cosign`, `finalize`, `cleanup`, `evidence`. A stage is the latest code-owned marker before an operation/group; it is neither proof of completion nor a causal diagnosis. The preexisting unguarded setup/umask boundary is unchanged.

`assetIndex` is -1 outside a download, otherwise0..10 in the unchanged fixed ASSETS insertion order. Each actual download resets HTTP context before its setup. `lastHttpState` is exactly `not-observed`, `response` or `http-error`; `lastHttpStatus` is0 or an exact builtin integer100..599. Booleans, strings, integer subclasses and coercion-bearing objects are not converted. Capture the original winning `response.status` operand once, after both existing with-context entries, then keep the original equality/URL predicate order and short-circuit acceptance. No additional status getter or URL read is introduced. Only exact `urllib.error.HTTPError` instances contribute error codes, through a builtin dictionary lookup on the nondelegating direct instance dictionary; no `.code`, `getattr`, body delegation, exception representation/type, URL/path, headers/body, environment or token is emitted.

Later stages may retain the explicitly named last HTTP observation even after `assetIndex` returns to-1; it is not an assertion that HTTP caused the failure. Every main call resets context. The failing snapshot is saved before cleanup, so successful cleanup cannot replace it with cleanup work. Cleanup failure still overrides reason to `cleanup`, reports cleanup false and marks the diagnostic stage `cleanup`; no success, signature or payload claim is restored. Existing reason selection, limits, signature calls, cleanup and stage API/return keys remain unchanged.

Successful default/preparation output remains byte-identical: no added success diagnostic. Failure still suppresses RAW/candidate/signature success claims. The new diagnostic participates in the unchanged262144-byte aggregate output check; the unchanged131072-byte RAW-line bound also remains. The evidence-limit fallback plus the fixed bounded diagnostic is small enough for the original aggregate bound. Synthetic actual-module regressions cover each selected frontier, safe HTTP code handling/body traps, single status read and context/predicate order, reset and snapshot/cleanup precedence, bounded canonical failure output, success bytes and preexisting operation traces. These tests run without artifact acquisition, native Codex/Cosign, Docker, provider or real authentication; they do not replace fresh exact-head hosted proof after any separately authorized application.
