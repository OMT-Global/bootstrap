# ADR-0025: Node 20-compatible Vitest 4 development toolchain

Status: Accepted

Acceptance covers the root-reviewed source/local migration stage. Independent human PR approval, hosted validation and publication remain separate.

Date: 2026-11-09

Governing issue: #63. ADR-0024 remains reserved for J0.

## Context

The compatible Stage A graph retained three inherited development advisory groups. Vitest4.1.12 removes the remaining vulnerable mocker/Tinypool family while supporting the existing Node20 baseline. A major test-tool/pool implementation transition requires actual behavior and type evidence; a zero registry audit alone is insufficient.

## Decision

Adopt the complete reviewed Vitest4.1.12 package/lock pair and retain Stage A's compatible Vite7/esbuild/CSS constraints. Preserve all production dependencies, MIT/notices, unrelated dev roots and package scripts/engines. Remove minWorkers only from Bootstrap's own fast/extended commands and two project-owned adjunct workflows. Keep maximums2/1, focused Node20 command, images, Node20.20.2/Ubuntu24.04, permissions, pins, timeouts and resources. Shared templates and legacy Vitest2 defaults stay unchanged; no pool/profile/concurrency configuration is added.

Establish a fresh worktree's own state through a separately approved real unchanged baseline apply before managed updates. Derive manifest/two scripts/sidecar through the real producer, with 47 selected paths, 49 claims and 50 state bindings. A render preview or mutable sidecar never substitutes for authority. Capture real event receipts, exact backups, admitted plans and fixed points; never copy state or manually edit hashes.

Actual ordinary Node20 runtime, changed-test strict typing and complete baseline/candidate typing comparison support this stage. The full strict check retains the same30 preexisting diagnostics and zero new ones; it is not reported as globally clean. No speculative API changes were needed. Use versioned primary Vitest4 contracts and installed types before any future adaptation, and fix only actual regressions.

## Consequences

The five development constraints need continued maintenance. Complete full/runtime audits now report zero locally, while actual installed component notices and optional-platform metadata remain separately inventoried; existing production notice records and original ownership confirmations are unchanged.

The unchanged 9b77 full-validation callee's independent bare npm check, genuine new-head hosted/native evidence, formal model review and human PR approval remain gates. This decision authorizes neither CI/provider/settings/home/cloud/release activity nor a merge/publication, and does not close all issue63 or consolidation acceptance.
